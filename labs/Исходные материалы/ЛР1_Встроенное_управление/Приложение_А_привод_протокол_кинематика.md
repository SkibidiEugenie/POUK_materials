## А.1. Интеллектуальный привод: регистровая модель

Классический хобби-сервопривод управляется шириной импульса, обратной связи не имеет, о своём состоянии не сообщает. **Интеллектуальный привод** содержит собственный микроконтроллер, замыкающий контур положения, а наружу выводит цифровую шину и **регистровую модель** — таблицу ячеек памяти, чтение и запись которых составляют весь интерфейс управления.

Dynamixel AX-12A: двигатель постоянного тока, редуктор, потенциометрический датчик угла, встроенный регулятор положения с настраиваемой зоной податливости, шина TTL до 1 Мбит/с.

| Адрес | Регистр | Назначение |
|---|---|---|
| 3 | ID | адрес привода на шине (1–253) |
| 5 | Return Delay Time | пауза перед ответом; заводское значение соответствует ≈500 мкс |
| 6, 8 | CW/CCW Angle Limit | пределы угла; 0/0 — режим непрерывного вращения |
| 24 | Torque Enable | подача момента (0 — вал свободен) |
| 30 | Goal Position | целевое положение, 0–1023 |
| 32 | Moving Speed | скорость движения к цели |
| 36 | Present Position | текущее положение, 0–1023 |
| 38 | Present Speed | текущая скорость |
| 40 | Present Load | оценка нагрузки |
| 43 | Present Temperature | температура, °C |

Привод является одновременно исполнительным устройством и датчиком: снятие «реальной траектории по энкодерам» в ЛР1 означает периодическое чтение регистра 36 у каждого привода.

**Практическое замечание.** Заводская задержка ответа (регистр 5) — типовая причина неожиданно медленного опроса: она добавляется к каждому обмену. Её уменьшение до десятков микросекунд ускоряет цикл чтения в разы и является одним из заданий со звёздочкой.

## А.2. Шина и протокол Dynamixel 1.0

Приводы соединены в цепочку на общей трёхпроводной линии (питание, земля, данные). Линия данных полудуплексная: в каждый момент передаёт одно устройство. Хозяин шины — контроллер: он посылает **инструкцию**, адресованный привод отвечает **статус-пакетом**. Отсюда ответ на вопрос, регулярно возникающий на защите: к плате идут три провода независимо от числа приводов.

### А.2.1. Кадр инструкции

```
0xFF 0xFF | ID | LENGTH | INSTRUCTION | PARAM 1 … PARAM N | CHECKSUM
```

- `0xFF 0xFF` — маркер начала кадра;
- `ID` — адресат (0xFE — широковещательный, ответ не предполагается);
- `LENGTH` = N + 2;
- `INSTRUCTION`: 0x01 — ping, 0x02 — чтение, 0x03 — запись, 0x83 — синхронная запись;
- `CHECKSUM` = ~(ID + LENGTH + INSTRUCTION + ΣPARAM) — младший байт суммы, инвертированный.

### А.2.2. Разбор кадра по байтам

Инструкция «привод № 3, перейти в положение 600 со скоростью 150». Регистр Goal Position — адрес 30 (0x1E), значение 600 = 0x0258 передаётся младшим байтом вперёд; следом записывается соседний регистр Moving Speed (адрес 32), 150 = 0x0096. Протокол допускает запись нескольких подряд идущих регистров одним кадром.

```
FF FF 03 07 03 1E 58 02 96 00 E4
│  │  │  │  │  │  └─────┴──┴──┴─ параметры: адрес 0x1E и данные 58 02 96 00
│  │  │  │  │  └─ начальный адрес записи (30)
│  │  │  │  └─ инструкция 0x03 (WRITE)
│  │  │  └─ LENGTH = 5 параметров + 2 = 7
│  │  └─ ID = 3
└──┴─ маркер кадра
```

Проверка контрольной суммы: 0x03 + 0x07 + 0x03 + 0x1E + 0x58 + 0x02 + 0x96 + 0x00 = 0x11B; младший байт 0x1B; инверсия ~0x1B = **0xE4**. Повреждённый кадр привод отбрасывает молча — правильное поведение протокола: лучше не сделать ничего, чем выполнить неизвестно что.

Упражнение «вычислить контрольную сумму заданного кадра вручную» входит в защиту ЛР1.

### А.2.3. Статус-пакет и диагностика

Ответ привода имеет ту же структуру, но вместо поля инструкции содержит поле **ERROR** — битовую маску (перегрев, перегрузка, выход за пределы угла, ошибка контрольной суммы принятого кадра). Прошивка, не читающая это поле, лишает себя штатной диагностики.

### А.2.4. Арифметика шины и синхронная запись

Запись уставки одному приводу: кадр инструкции 9 байт, статус-ответ 6 байт. На скорости 1 Мбит/с байт с учётом старт- и стоп-битов занимает 10 мкс, то есть ≈150 мкс на обмен, плюс задержка ответа привода (заводская ≈500 мкс). Шесть приводов последовательно — до ≈4 мс только на запись, причём приводы стартуют **неодновременно**, что на согласованных движениях звеньев даёт видимый излом траектории.

Инструкция **sync write** (0x83) устраняет обе проблемы: один широковещательный кадр несёт уставки всем приводам (для шести приводов и двухбайтового регистра — 8 + 6 × 3 = 26 байт ≈ 260 мкс), ответы не передаются, приводы принимают уставки одновременно. Выигрыш по времени — на порядок, по согласованности движения — качественный.

## А.3. Единицы на борту

Согласуются три системы:

- **физическая**: углы в радианах, координаты в метрах — в них решается кинематика;
- **приводная**: безразмерные отсчёты 0–1023 на диапазон 0–300°; среднее положение — 512;
- **протокольная**: байты кадров.

Коэффициент перевода: одна единица ≈ 300°/1024 ≈ 0,29° ≈ 0,00511 рад. В учебной прошивке он присутствует под именем `del = 0.00511327`; преобразование угла α (рад) в уставку:

`AL = 512 + round(α / del)`

Смещение 512 переносит нуль в среднее положение, соответствующее вертикальной сборке манипулятора. Обратное преобразование восстанавливает угол из телеметрии.

**Правило трёх точек.** При работе с любым новым приводом первым делом выписываются оба преобразования и проверяются на трёх положениях: край диапазона, центр, противоположный край. Это дешёвая страховка от перепутанного знака, забытого смещения и градусов вместо радиан — источника примерно половины ошибок в лабораторных работах.

**Стоимость плавающей точки.** На ядре Cortex-M3 блок операций с плавающей точкой отсутствует: `sin`, `atan2`, `sqrt` эмулируются программно и стоят сотен тактов каждая. Для одного пересчёта ОЗК на 20 точках траектории это несущественно; для контура на килогерце — уже определяет бюджет. Промышленная практика на таких ядрах — целочисленная арифметика с фиксированной точкой; в курсе мы остаёмся на float, но студент обязан понимать границу применимости.

## А.4. Кинематика стенда

### А.4.1. Схема и соглашение

Манипулятор имеет пять приводных степеней (шестой привод — схват): O₁ — поворот основания вокруг вертикальной оси; O₂, O₃, O₄ — «плечо», «локоть», «запястье» в одной вертикальной плоскости; O₅ — поворот схвата вокруг продольной оси. Длины условных звеньев: l₁ = 0,103 м; l₂ = 0,1045 м; l₃ = 0,079 м; l₄ = 0,169 м (уточните по своей сборке).

Пять степеней не дают произвольной ориентации схвата, поэтому принимается соглашение: **выходное звено вертикально** (схват смотрит вниз). Тогда

α₂ + α₃ + α₄ = π

и задача распадается на независимый поворот основания и плоскую двухзвенную задачу.

### А.4.2. Обратная задача

Поворот основания: α₁ = atan2(y, x); привод O₅ компенсирует поворот схвата: α₅ = α₁.

Плоская часть. Горизонтальная проекция k = √(x² + y²); приведённая высота z_r = z + (l₄ − l₁) — перенос начала координат в ось O₂ с учётом вертикального звена l₄. Расстояние от O₂ до точки крепления запястья: d = √(k² + z_r²).

Треугольник со сторонами l₂, l₃, d решается теоремой косинусов:

α₂ = π/2 − ( atan2(z_r, k) + arccos( (d² + l₂² − l₃²) / (2 d l₂) ) )

α₃ = π − arccos( (−d² + l₂² + l₃²) / (2 l₂ l₃) )

α₄ = π − (α₂ + α₃)

Отсчёт α₂ от вертикали (слагаемое π/2) соответствует сборке: в нулевой конфигурации все звенья вертикальны, все приводы в положении 512.

**Условие существования решения**: |l₂ − l₃| ≤ d ≤ l₂ + l₃. Верхняя граница — сфера радиуса l₂ + l₃ вокруг O₂ (вытянутая рука, вырожденная конфигурация: якобиан теряет ранг, малое приращение координаты требует большого приращения углов); нижняя — мёртвая зона у оси. Практическое следствие наблюдается в ЛР1 непосредственно: точки траектории вблизи границы рабочей зоны отрабатываются с наибольшей ошибкой.

**Две конфигурации.** Теорема косинусов не различает «локоть вверх» и «локоть вниз»: обе тройки углов приводят схват в одну точку. Полная реализация обязана вычислить обе ветви, проверить каждую на пределы приводов и выбрать допустимую.

### А.4.3. Прямая задача для проверки по телеметрии

k = l₂ sin α₂ + l₃ sin(α₂ + α₃) — горизонтальная составляющая (при отсчёте углов от вертикали);

z = l₁ + l₂ cos α₂ + l₃ cos(α₂ + α₃) − l₄ — высота с учётом вертикального запястья;

x = k cos α₁, y = k sin α₁.

Подстановка углов, считанных из регистров 36 в момент отработки траектории, даёт реальную траекторию схвата; её наложение на заданную — главный график отчёта.

**Источники расхождения** (требуется разделить в отчёте): люфт редукторов (доминирует), дискретность датчика (0,29° на плече ≈ 0,35 м даёт ≈ 1,8 мм), динамическая ошибка регулятора привода под нагрузкой, хордовая погрешность дискретизации (см. А.5).

## А.5. Дискретизация траектории и контроль достижения

**Дискретизация.** Окружность радиуса R заменяется N хордами. Максимальное отклонение хорды от дуги (стрелка сегмента):

e = R (1 − cos(π/N)) ≈ R π² / (2 N²)

Для R = 30 мм и N = 20: e ≈ 0,37 мм — на порядок меньше люфта, поэтому увеличивать N бессмысленно; при N = 8 получаем e ≈ 2,3 мм, что уже сравнимо с люфтом. Число точек в отчёте должно быть следствием такого расчёта, а не данностью задания.

**Профиль перехода.** Привод отрабатывает скачок уставки со скоростью из регистра 32; последовательность скачков даёт старт-стопное движение. Базовый вариант этим ограничивается; вариант со звёздочкой строит трапецеидальный профиль скорости.

**Контроль достижения.** Команду на следующую точку нельзя давать по таймеру: при затянувшейся отработке накапливается срез углов. Правильная схема — цикл ожидания: читать текущие положения, сравнивать с целевыми по допуску ε, выходить по достижении либо по тайм-ауту с диагностикой. Обоснование допуска: меньше люфта добиться невозможно, поэтому ε выбирается порядка люфта (в учебном решении ≈ 0,08 рад ≈ 16 отсчётов).

Пара «допуск + тайм-аут» — первый в курсе пример **контракта реального времени**: система обещает либо результат, либо явный отказ за ограниченное время. Тот же шаблон повторится в протоколе ЛР2 (тайм-аут кадра) и в интерфейсе цели ЛР3–ЛР4 (глава 4, §4.4).

## А.6. Структура прошивки по слоям

Учебная прошивка при всей компактности демонстрирует расслоение, обязательное для промышленного встроенного ПО, и является реализацией принципа 4C (глава 1, §1.6):

| Слой | Содержание в ЛР1 | Промышленный аналог | Судьба в курсе |
|---|---|---|---|
| Драйвер шины | инициализация, чтение/запись положений | HAL, драйверы полевых шин | ЛР4-Б: тот же слой на контроллере робота |
| Преобразование единиц | коэффициент, смещение, ограничения | нормализация сигналов | остаётся неизменным |
| Кинематика | ОЗК, ПЗК для телеметрии | библиотека движения | ЛР4: заменяется плагином планировщика |
| Сценарий | обход точек, контроль достижения | исполнитель программы движений | ЛР3: заменяется автоматом состояний |
| Связь с верхним уровнем | вывод телеметрии, разбор команд | полевой протокол | ЛР2: заменяется протоколом v2 (COBS, CRC-32, подтверждения) |

**Критерий приёмки по структуре**: замена драйвера шины не должна требовать правки кинематики.

## А.7. Карта типовых дефектов учебной прошивки

Историческая прошивка стенда (`OZK_funk.ino`) содержит характерный набор дефектов встроенного ПО. Их разбор — обязательная часть занятия и защиты.

```cpp
float l1 = 0.103;            // (в) длины звеньев — глобальные переменные
float del = 0.00511327;      // рад → отсчёты привода

void OZK(float x, float y, float z, float fi){
  z_r = z + (l4 - l1);
  k   = sqrt(x*x + y*y);
  d   = sqrt(k*k + z_r*z_r);
  alf1 = atan(y/x);                                   // (а) atan вместо atan2
  alf2 = pi/2 - (atan(z_r/k)
       + acos((d*d + l2*l2 - l3*l3)/(2*d*l2)));       // (б) acos без проверки
  alf3 = pi - acos((-d*d + l2*l2 + l3*l3)/(2*l2*l3));
  alf4 = pi - (alf2 + alf3);
  AL2  = 512 + int(alf2/del);
  dxl.setGoalVelocity(2, 100);                        // (в) магическое число
  dxl.setGoalPosition(2, AL2);                        // (г) шесть копий вместо цикла
  ...
}
void loop() {
  OZK(0.1, 0, 0.03,  90); delay(5000);                // (д) блокирующая пауза
  OZK(0.1, 0, 0.03, -90); delay(5000);
}
```

Список дефектов и цена каждого:

**(а)** `atan(y/x)` теряет квадрант и делит на ноль при x = 0. Лечится `atan2(y, x)`.

**(б)** При недостижимой точке аргумент `arccos` выходит за [−1; 1], результат — NaN; `int(NaN/del)` даёт мусор, который молча уходит в привод. Самый опасный дефект списка: непредсказуемый рывок вместо отказа. **Исправление обязательно для зачёта работы.**

**(в)** Магические константы (длины звеньев, скорости) рассыпаны по телу функции вместо именованных параметров в одном месте — нарушение заботы Configuration.

**(г)** Шесть копий кода вместо цикла: любое изменение требует шести правок.

**(д)** Блокирующие задержки в цикле: пять секунд прошивка не читает команды, не выдаёт телеметрию и не проверяет защиты — цикл управления мёртв (глава 1, §1.7.2, §1.8).

**(е)** Поле ERROR статус-пакета не читается: штатная диагностика привода не используется.

## А.8. Образцовая реализация обратной задачи

Пакет `angle_arm` целевого робота содержит класс `RoboticArm`, метод `InversProblem` которого показывает, чем полная инженерная реализация отличается от минимальной учебной (код сокращён до сути):

```python
def InversProblem(self, x, y, z, pitch=0, roll=0):
    q5 = roll                    # ориентация схвата — параметр, а не соглашение
    q1 = atan2(y, x)
    w  = sqrt(x**2 + y**2)
    z1 = (z - l1) - (l4 + l5)*sin(pitch)   # перенос цели из схвата
    w1 = w - (l4 + l5)*cos(pitch)          # в точку крепления запястья
    ...
    D = b**2 - 4*a*e             # дискриминант: пересечение окружностей
    if D < 0:
        return False, [0,0,0,0,0]          # цель недостижима — ЯВНЫЙ отказ
    z2_1 = (-b + sqrt(D))/(2*a)            # первая ветвь решения
    z2_2 = (-b - sqrt(D))/(2*a)            # вторая ветвь
    ...
    ok, q1, q2, q3, q4, q5 = self.__ValidatingOfJointAngle(...)
    return ok, [q1, q2, q3, q4, q5]
```

Четыре отличия от учебной версии:

1. ориентация схвата — параметр (pitch, roll), а не зашитое соглашение: один код обслуживает захват и сверху, и сбоку;
2. недостижимость возвращается явным кодом, а не NaN;
3. обе ветви решения вычисляются всегда;
4. выбор ветви делает отдельная процедура валидации по табличным пределам суставов, вынесенным в одно место класса.

**И поучительный финал.** Даже в этом коде живёт дефект: проверка первого сустава записана как `if (q1 >= joint_1_l or q1 <= joint_1_u)` — логическое **или** вместо **и**. Условие истинно при любом q1, то есть проверка первой оси не работает вовсе, и за годы эксплуатации этого никто не заметил: цель всегда лежала в допустимом секторе. Найти этот дефект, объяснить, почему он не проявлялся, и указать запрос, при котором он привёл бы к удару манипулятора о корпус, — штатное упражнение занятия.

Вывод, полезный для всего курса: код, который «работает», и код, который корректен, — разные вещи, и различие вскрывается только чтением.

## А.9. Бюджет времени цикла прошивки

Инженерный навык, который тренирует ЛР1, — посчитать состав итерации цикла до написания кода:

| Составляющая | Оценка |
|---|---|
| Разбор команды из последовательного порта | ≈0,1 мс |
| Пересчёт ОЗК (эмуляция плавающей точки) | 0,3–0,5 мс |
| Запись уставок шести приводам (одиночные кадры) | ≈1,3 мс без учёта задержки ответа |
| Чтение шести положений (с заводской задержкой ответа) | ≈4,3 мс |
| **Итого** | **≈6 мс → до ≈160 Гц** |

Для позиционного управления этого достаточно с запасом. Расчёт, проделанный **до** первого запуска, отличает инженерную работу от подбора наугад; в отчёте он обязателен.
