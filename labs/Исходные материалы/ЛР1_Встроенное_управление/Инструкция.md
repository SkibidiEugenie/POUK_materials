## 1. Подготовка — до лабораторного занятия (≈40 мин)

Установка поддержки платы длится долго: выполните её дома.

1. Установите **Arduino IDE** (arduino.cc → Software).
2. `Файл → Настройки → Дополнительные ссылки для менеджера плат` — добавьте ссылку пакета OpenCM9.04 из e-Manual ROBOTIS (раздел OpenCM9.04 → Arduino IDE). Актуальный адрес вида
   `https://raw.githubusercontent.com/ROBOTIS-GIT/OpenCM9.04/master/arduino/opencm_release/package_opencm9.04_index.json`.
3. `Инструменты → Плата → Менеджер плат` — найдите «OpenCM9.04», установите.
4. `Инструменты → Управлять библиотеками` — установите **Dynamixel2Arduino**.
5. Установите Python 3 и пакеты для скрипта траектории: `python -m pip install pyserial matplotlib`.
6. Склонируйте репозиторий бригады с каталогом `code` (см. [регламент практикума](../README.md)).

**Контроль подготовки:** пример `Файл → Примеры → Dynamixel2Arduino → basic → scan_dynamixel` компилируется для платы OpenCM9.04.

## 3. Базовый маршрут

### Шаг 0. Знакомство со стендом (15 мин)

Зарисуйте схему стенда: где контроллер, куда идёт шина, как пронумерованы приводы (ID 1–6 снизу вверх; ID 6 — схват). Измерьте длины условных звеньев и сравните с l₁ = 0,103; l₂ = 0,1045; l₃ = 0,079; l₄ = 0,169 м. Если расхождение больше 2 мм, используйте свои значения везде: в прошивке (`L1…L4`) и в скрипте (`L1, L2, L3, L4`).

### Шаг 1. Связь с приводами (20 мин)

1. Откройте `code/lab1/lab1_skeleton/lab1_skeleton.ino` в Arduino IDE, выберите плату OpenCM9.04 и порт, загрузите.
2. Откройте монитор порта: **57600 бод**, окончание строки — «Новая строка» (`\n`).
3. При старте каркас сам сканирует шину; повторно — командой `S`. Ожидаемый вывод: `ID 1: ok, pos=…` для всех шести приводов.
4. Запишите положения при вертикальной сборке (ожидаемо около 512).

Если привод не отвечает — см. раздел 5 «Типовые ошибки».

### Шаг 2. Пределы суставов (20 мин)

Команда `P <id> <pos>` двигает один привод. Найдите безопасные пределы каждого сустава **малыми шагами** (20–30 отсчётов): рука не должна касаться стола, корпуса и собственных звеньев. Уточните массивы `JOINT_MIN[]`/`JOINT_MAX[]` каркаса. Стартовые значения покрывают окружности всех вариантов, но ваша сборка может отличаться.

В отчёт: таблица пределов в отсчётах и радианах с указанием, чем ограничен каждый предел (упор, соседнее звено, стол).

### Шаг 3. ОЗК: движение в точку (40 мин)

Реализуйте в каркасе функцию `bool solveIK(float x, float y, float z, float out[5])` по формулам §А.4.2. Каркас содержит подсказки `TODO шаг 3.1–3.3`.

Обязательные требования:

- **проверка достижимости до вызова `acos`**: |l₂ − l₃| ≤ d ≤ l₂ + l₃; при нарушении — сообщение и `return false`;
- `atan2`, а не `atan`;
- перевод результата в отсчёты и проверка каждого сустава по `JOINT_MIN/MAX`; при нарушении — сообщение с номером сустава и `return false`;
- **ни одной записи в привод**, если хоть одна проверка не прошла.

Команда `G <x> <y> <z>` (миллиметры) ведёт схват в точку. Проверьте:

| Точка, мм | Ожидаемое поведение |
|---|---|
| центр окружности вашего варианта, поднятый на 20 мм | переход в точку |
| точка на окружности варианта | переход в точку |
| (0, 0, 450) | отказ: цель дальше вытянутой руки |
| (400, 0, 30) | отказ: цель дальше вытянутой руки |
| точка, для которой нарушается предел одного из суставов (подберите сами) | отказ с номером сустава |

Сверьте углы, которые печатает прошивка, с расчётом по формулам вручную или скриптом (`solve_ik` в `lab1_traj_and_plots.py`): расхождение больше 1 отсчёта — ошибка.

### Шаг 4. Контроль достижения (30 мин)

Реализуйте `bool waitReach(const int32_t target[5])`: циклически читать положения приводов 1–5, находить максимум |факт − цель|, выходить с `true`, если он не больше `EPS_TICKS`, и с `false` по тайм-ауту `REACH_TO_MS`. Телеметрию внутри ожидания печатать не чаще раза в 50 мс — планированием по `millis()`, без `delay()`.

Обоснуйте выбор ε и тайм-аута:

- ε не может быть меньше люфта и дискретности датчика: измерьте люфт — отклоните звено рукой в обе стороны при поданном моменте и запишите разброс показаний (§А.5); типично 12–20 отсчётов;
- тайм-аут — из самого длинного перехода между соседними точками при заданной скорости плюс запас.

Проверка: во время перехода **подоприте звено мягким предметом** (не пальцем) — функция обязана вернуть отказ по тайм-ауту с сообщением `REACH: timeout`.

### Шаг 5. Окружность варианта (40 мин)

1. Выберите число точек N расчётом: стрелка сегмента e = R(1 − cos(π/N)) должна быть заметно меньше люфта в миллиметрах на плече до схвата (§А.5). Запишите расчёт в отчёт.
2. Сгенерируйте траекторию своего варианта (аргументы: R, центр x, y, z, N — миллиметры):

   ```bash
   cd code/lab1
   python lab1_traj_and_plots.py gen 30 100 0 30 20
   ```

   Скрипт пишет `lab1_skeleton/circle_traj.h` (уставки в отсчётах) и `traj_ideal.csv` (заданная окружность). Если скрипт сообщает о недостижимой точке — проверьте параметры варианта и длины звеньев.
3. Пересоберите и загрузите прошивку. Команда `C` — обход окружности с контролем достижения. Проверьте 2–3 круга.

### Шаг 6. Телеметрия и график (35 мин)

При обходе окружности прошивка печатает строки `T,<мс>,<p1>,…,<p6>` (отсчёты).

1. Закройте монитор порта (порт может занимать только одна программа).
2. Запишите журнал: `python lab1_traj_and_plots.py log COM5 reports/lab1/circle.csv` (в Linux порт вида `/dev/ttyACM0`). После сообщения «Пишу…» отправьте команду `C` (например, из второго окна терминала или кнопкой платы — либо временно добавьте автозапуск обхода в `setup()`), дождитесь `CIRCLE: done`, остановите запись `Ctrl+C`.
3. Постройте график: `python lab1_traj_and_plots.py plot reports/lab1/circle.csv`. Скрипт решает ПЗК по телеметрии (§А.4.3) и накладывает реальную траекторию на заданную → `plot_circle.png`.

### Шаг 7. Анализ (20 мин)

1. Вычислите радиальное отклонение каждой точки телеметрии от окружности варианта: максимум, среднее, p99.
2. Разделите источники расхождения (§А.4.3): люфт редукторов, дискретность датчика, статическая ошибка привода под нагрузкой (звено 2 проседает под весом руки), хордовая ошибка дискретизации e, динамика перехода. Для каждого — оценка в миллиметрах; для доминирующего — эксперимент или расчёт, который это подтверждает.
3. Составьте бюджет итерации цикла прошивки (§А.9): что в нём доминирует и сколько времени занимает обход одной точки.

## 4. Задания со звёздочкой — подсказки

- **★1 sync write.** В Dynamixel2Arduino есть групповые операции записи (`syncWrite`); подготовьте структуру на пять приводов один раз в `setup()`. Время замеряйте `micros()` до и после рассылки, по 100 измерений; в отчёт — p50 и максимум для обоих вариантов.
- **★2 трапеция.** Разбейте переход между точками на промежуточные уставки с шагом 10–20 мс; профиль скорости — разгон, постоянная скорость, торможение. Сравните графики положения одного сустава во времени до и после.
- **★3 телеметрия по таймеру.** Перенесите печать `T,…` в планировщик `if (micros() - t_next >= 0) { … t_next += PERIOD; }` в `loop()`; разброс периода считайте по столбцу времени журнала.
- **★4 Return Delay Time.** Запись в регистр 5 выполняется один раз и сохраняется в памяти привода — **запишите исходное значение** и верните его после опыта.

## 5. Типовые ошибки

| Симптом | Вероятная причина | Что сделать |
|---|---|---|
| Arduino IDE не видит порт | кабель только для зарядки; не установлен драйвер | другой кабель; в Windows — драйвер из пакета платы |
| Загрузка обрывается | плата занята программой, которая держит порт | закройте монитор порта и скрипт; при повторе — подключите USB с зажатой кнопкой USER платы (режим загрузчика) и загрузите снова |
| `ID n: NO RESPONSE` у всех | нет питания 12 В; неверная скорость шины | проверьте блок питания; в `busInit()` — 1 000 000 бод и протокол 1.0 |
| Не отвечает один привод | обрыв в цепочке; у привода другой ID | проверьте разъёмы до этого привода; сканирование других ID |
| Рывок в случайное положение при команде `G` | NaN или отсчёты вне диапазона ушли в привод | проверка достижимости до `acos`, проверка пределов до записи |
| Схват приходит «не туда», но плавно | перепутан знак угла или единицы (градусы/радианы, мм/м) | правило трёх точек (§А.3); сверка углов с расчётом скрипта |
| `REACH: timeout` на каждой точке | ε меньше люфта; привод упирается в предел | измерьте люфт; проверьте пределы шага 2 |
| В мониторе «кракозябры» | скорость монитора не 57600 | выставьте 57600 бод |
| Окружность «сплюснута» по одной оси | неверная длина звена | измерьте длины (шаг 0), поправьте в прошивке и скрипте |
